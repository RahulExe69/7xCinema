# 7xCinema — Capacitor application

The primary app shell is React + TypeScript + Vite inside Capacitor 8. The older `android-app/` Kotlin/Compose project remains in this repository as a player/aggregation feasibility reference; it is not the new application shell.

## Features in this milestone
- Responsive cinema-inspired UI for Android and web.
- Local starter catalogue, title details, filters, and a device-local watchlist.
- One search entry point that fans out concurrently to every enabled catalogue adapter, streams partial results, and isolates provider errors/timeouts.
- An Internet Archive adapter that searches only explicit Public Domain Mark/CC0 declarations, verifies that item metadata contains a compatible MP4, preserves the original item/licence links, and offers direct playback.
- An experimental bundled MovieBox-TUI Rust engine for Android ARM64. A single query fans out across MovieBox, 4KHDHub, Dramachi, CircleFTP (BDIX), and DhakaFlix (BDIX); the engine merges title matches while preserving provider-specific IDs and reported language labels.
- Provider-specific release selection and series episode selection. The selected release is resolved by its source ID/index, then handed to the native Media3 player with supported source request headers.
- Optional live TMDB multi-search and trending catalogues when a TMDB v3 API key is configured.
- Official watch/rent/buy destinations reported by TMDB for a selected country.
- Optional Jellyfin personal-library connection: sign in to a server you own or are authorised to use, store the native session token with Android secure storage, browse recent library titles and resumable movies/episodes, and play with Media3. Resume position and progress are read/written through the Jellyfin server.
- Accurate metadata language labelling: original-language metadata is not presented as a verified audio or subtitle track.
- One-tap Watch actions on title cards and a watch-first source chooser. Valid direct media URLs returned by adapters open the player automatically; titles with no direct source show official destinations/trailers first. Manual URL entry is available only under Advanced.
- Native AndroidX Media3 playback bridge with player controls and actual reported audio/subtitle-track selection; web preview uses HTML5 video for compatible direct HTTP(S) URLs.
- Unit tests for deduplication, provenance, provider failure isolation, progressive results, and timeouts.

## Setup
Requires Node.js 22.12+ for Vite 7 and Capacitor 8, plus Android Studio / Android SDK for native Android builds.

```sh
cd capacitor-app
npm install
npm run dev
npm test
npm run build
npx cap add android
npx cap sync android
npx cap open android
```

For a subsequent web build update, run `npm run android:sync`. The Android project is generated by Capacitor and ignored by Git in this first migration milestone; GitHub Actions generates it in a clean runner and publishes a debug APK artifact.

## Jellyfin personal library

Open **Settings → Jellyfin personal library**, enter your own server URL and credentials, then connect. The password is sent directly to that server and cleared from the form after a successful login. On Android, the resulting session token is stored using secure storage backed by the platform keystore; the browser preview keeps it in memory only. HTTPS is recommended for any remote server. Plain HTTP should be limited to a trusted private network. Disconnecting clears the saved token. The native player uses the session token in request headers—not the media URL—and periodically reports progress to the configured Jellyfin server. This integration supports personal libraries you are authorised to access; it is not a public movie-stream source.

## TMDB setup
Open **Settings**, paste your own TMDB v3 API key, choose the region, and save. The key is stored in this app's local WebView storage. Do not paste a privileged server secret or access token. A build may alternatively supply `VITE_TMDB_API_KEY`; build-time values are bundled into the client and should be treated as public.

TMDB data provides metadata and reported official watch destinations, not playback URLs. Review TMDB's terms and branding requirements before public distribution.

## Limits and verification status
The MovieBox-TUI source integrations are experimental: successful code/build integration does not guarantee a provider is reachable, authorised for a particular title/use, or able to resolve a playable stream from the users network. The current all-provider search includes five built-in sources; optional community Stremio add-ons are not exposed yet. Source language labels are metadata, not proof of an embedded selectable audio track. External subtitle selection from provider metadata is not yet wired into the player; the native player still exposes tracks it actually detects. The web preview uses HTML5 video and cannot emulate every provider header needed by a direct release. The Android ARM64 build and JS tests are covered by CI, but live provider-by-provider playback, network/BDIX reachability, lifecycle, audio/subtitle behavior and resume on a physical phone remain release checks. Review upstream rights/terms and per-provider behavior before publicly advertising any source as supported.

## Build output
The `Capacitor Android Build` GitHub Actions workflow builds the pinned MovieBox-TUI Rust engine for Android ARM64, bundles its shared library, runs JS tests, builds the web assets, generates the Android shell with both native plugins, builds `app-debug.apk`, and uploads it as `7xCinema-Capacitor-Debug`. The engine is served only over loopback with an ephemeral port and random process token; no hosted scraping API is required.


## Open-license archive safety
The archive adapter only accepts item metadata that explicitly names the Creative Commons Public Domain Mark 1.0 or CC0 1.0 URL and contains an MP4 file. It retains links to the original item and licence so the user can review them. Those licence fields are uploader-supplied metadata, not independent rights verification; check the item page before reuse or redistribution. This adapter is not an endorsement that every Internet Archive upload is lawful or public domain. Internet Archive supports metadata search and item metadata APIs; the implementation uses those APIs directly and does not proxy or rehost the media.
