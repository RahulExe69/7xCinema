# 7xCinema — Capacitor application

The primary app shell is React + TypeScript + Vite inside Capacitor 8. The older `android-app/` Kotlin/Compose project remains in this repository as a player/aggregation feasibility reference; it is not the new application shell.

## Features in this milestone
- Responsive cinema-inspired UI for Android and web.
- Local starter catalogue, title details, filters, and a device-local watchlist.
- One search entry point that fans out concurrently to every enabled catalogue adapter, streams partial results, and isolates provider errors/timeouts.
- An Internet Archive adapter that searches only explicit Public Domain Mark/CC0 declarations, verifies that item metadata contains a compatible MP4, preserves the original item/licence links, and offers direct playback.
- Optional live TMDB multi-search and trending catalogues when a TMDB v3 API key is configured.
- Official watch/rent/buy destinations reported by TMDB for a selected country.
- Accurate metadata language labelling: original-language metadata is not presented as a verified audio or subtitle track.
- Native AndroidX Media3 playback bridge with player controls and actual reported audio/subtitle-track selection; web preview uses HTML5 video for compatible direct HTTP(S) URLs.
- Unit tests for deduplication, provenance, provider failure isolation, progressive results, and timeouts.

## Setup
Requires Node.js 22.12+ for Vite 7 and Capacitor 8, plus Android Studio / Android SDK for native Android builds.

```sh
cd capacitor-app
npm install
npm run dev
npm test
npm run build
npx cap add android
npx cap sync android
npx cap open android
```

For a subsequent web build update, run `npm run android:sync`. The Android project is generated by Capacitor and ignored by Git in this first migration milestone; GitHub Actions generates it in a clean runner and publishes a debug APK artifact.

## TMDB setup
Open **Settings**, paste your own TMDB v3 API key, choose the region, and save. The key is stored in this app's local WebView storage. Do not paste a privileged server secret or access token. A build may alternatively supply `VITE_TMDB_API_KEY`; build-time values are bundled into the client and should be treated as public.

TMDB data provides metadata and reported official watch destinations, not playback URLs. Review TMDB's terms and branding requirements before public distribution.

## What this is not yet
This migration does **not** claim a finished third-party stream resolver or a connected library of live playback providers. The current player is a direct-URL WebView player, not the native Media3 player and not a DRM bypass. HLS/DASH format support varies by device. Production provider adapters still require their own licence/terms review, documented permissions, real-world tests, and source-specific failure handling. Physical-device playback testing and individually reviewed, authorised source integrations remain explicit next milestones.

## Build output
The `Capacitor Android Build` GitHub Actions workflow runs tests, builds the web assets, generates the Android shell, builds `app-debug.apk`, and uploads it as `7xCinema-Capacitor-Debug`.


## Open-license archive safety
The archive adapter only accepts item metadata that explicitly names the Creative Commons Public Domain Mark 1.0 or CC0 1.0 URL and contains an MP4 file. It retains links to the original item and licence so the user can review them. Those licence fields are uploader-supplied metadata, not independent rights verification; check the item page before reuse or redistribution. This adapter is not an endorsement that every Internet Archive upload is lawful or public domain. Internet Archive supports metadata search and item metadata APIs; the implementation uses those APIs directly and does not proxy or rehost the media.
